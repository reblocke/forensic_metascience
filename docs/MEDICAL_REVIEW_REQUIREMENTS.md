# FM-MED-01 engineering requirement audit

This audit supplements the [27-scenario acceptance matrix](MEDICAL_REVIEW_ACCEPTANCE.md).
The immutable [ticket](MEDICAL_REVIEW_TICKET.md), rather than the implementation,
defines scope. Implementation is present for WP1–WP5's offline engineering
deliverables. Corrected canonical report/CLI/R/Quarto checks and all-page visual inspection
passed locally; final acceptance still requires delivered-head Python, native-R
and report receipts.
Live operational acceptance and medical performance qualification remain separate,
unestablished gates. All automated medical fixtures are synthetic or supplied
semantic responses; they establish interfaces and safeguards, not clinical
detection performance, authenticated human credentials or source fidelity.

## Acceptance decision

The requirement audit found clipped identifier labels despite a passing render.
A failing regression preceded a display-only correction: evaluation identifiers
wrap at 16 characters and labels are separate values. Shared appraisal display
keeps its previous default. The corrected canonical suite passed five cases in
495.55s; all 70 PDF pages were visually inspected and text bounds verified.
Twenty existing report/navigation cases, two actual rollback cases and two
required-runtime refusal cases also passed. Exact source/model values are intact.

Final engineering acceptance still requires terminal, nonempty, zero-failure/
error/skip Python, native-R and report receipts on the delivered PR head, with
required runtime/report artifacts and matching companion hashes. The handoff
records local/prior-head evidence; the PR records the final delivered-head gate.
A pending hosted gate is not a passing gate.

The ticket's blocked-live and pending-medical alternatives are implemented;
they are not waivers of operational/scientific qualification. Future enablement
requires source/provider/search authorization, qualified execution controls,
domain source adjudication, approved criteria before unblinding, sufficient
held-out results and an explicit promotion decision. No such acceptance or
default enablement occurred during engineering delivery.
